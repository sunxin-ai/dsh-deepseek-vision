# 视觉保真判定 · 基准评分规范

适用于评估「一个视觉模型能否胜任设计稿 vs 前端实现的保真度判定」。

与单次实验的 `SCORE.md` 不同，本规范是**可复用的方法**：换模型、换设计稿、换实现，都按这套流程和口径重跑。

---

## 1. 这个基准回答什么问题

> 把设计稿和实现截图交给视觉模型，它能否**说出可执行的语义级差异**？

「可执行」是关键。三种输出的价值天差地别：

| 输出 | 价值 |
|---|---|
| 「两张图看起来有些不同」 | **无用** |
| 「颜色不一致」 | **接近无用** —— 无法据此改代码 |
| 「进度环 A 是珊瑚橙、B 是芥末黄，应改回暖橙色系」 | **可执行** |

只有第三种能驱动收敛循环。基准必须能区分这三者。

## 2. 夹具构造规范

### 2.1 三件套

| 件 | 要求 |
|---|---|
| **设计稿** | 真实生成或真实设计产出，不可手绘简化。需含足够多的可检元素：多级字号、图标、图表、色彩层次 |
| **忠实实现 v1** | 尽最大努力还原。**它是误报率的对照组**，不是陪衬 |
| **注入版 v2** | v1 + 定量注入的已知缺陷，每处缺陷精确对应一个保真面 |

**v1 必须真的忠实。** 若 v1 本身就漏洞百出，误报率无从测量 —— 模型报的每一条都可能是真的。

### 2.2 夹具自证（第一位，先于一切模型讨论）

**每个中间产物都必须程序化断言，否则整轮基准会安静地跑在垃圾输入上。**

本基准第一轮的对比图是**两个空白框加两行标注**——拼图脚本用 `page.setContent()` 加载 `file://` 图片，
而 `setContent` 的文档源是 `about:blank`，其下的 `file://` 子资源被浏览器静默拦截。
`waitForLoadState('networkidle')` 照样返回成功：被拦截的请求不计入在途请求。

于是模型如实回答「图像未加载」，被记成了「模型自称看不见却编造分析」这一「危险失败模式」，
并据此写出了「必须分区送检」的架构结论。**一个未断言的中间产物，污染了下游全部判断。**

最低要求：

- 拼图一律走 data URI，截图前断言每张图 `naturalWidth > 0`
- 截图后断言像素尺寸与预期一致（偏差 >1px 失败）
- **每次评测必须包含一格「已知空白图」对照**。若锚点探针在空白图上也「答得出」，
  说明评分口径在放水 —— 这一格是评分体系自身的体检，不是被测项
- 任何一条 finding 写下之前，先确认输入图不是空白

### 2.3 像素归一化（做不到就别开始）

- 实现截图的像素尺寸必须**与设计稿完全一致**，靠视口 + `deviceScaleFactor` 达成，不靠事后缩放
- 截图前断言实际渲染尺寸，偏差 >1px 直接失败
- 裁掉浏览器 chrome、画布留白、设备边框

**归一化不到位时，模型报的差异大部分是缩放和裁切造成的假差异，基准直接失效。**

### 2.4 拼图

左 A 设计稿、右 B 实现，**图上不写任何标注文字**。理由：多数视觉工具只支持单图输入，而「分两次看图」不等于「并排对比」；标注文字会被读成页面内容（问大标题，答「A — DESIGN (source of truth)」）。哪边是哪边由提示词声明。

**送检粒度由锚点探针自适应决定，不预设分区。** 实测 2×2 因子（粒度 × 输入方式）四格无显著差别，`qwen3.8-max` 四格均 6/6。先整页，锚点过就整页判；锚点失败才细分。

**双图输入不优于拼图，且成本翻倍。** 素材判定上还更差：单看一张裁剪图时把房子图标读成「一本书」，并排放在一起反而认得出 —— 并排本身提供了对比锚点。

需要细分时：

- 区块边界取自**参考实现的真实 bounding box**，不用等分网格（等分会把一个卡片切成两半）
- 两个 arm 用**同一组 y 坐标**切，且该坐标一律取自参考实现 —— 若从被测版本取，间距类缺陷会连同窗口一起平移，模型永远看不到它
- 相邻区块各外扩约 20 CSS px，保证跨区边界的间距问题两边都能看到
- 分区后必须换用**分区提示词**。沿用整页提示词（里面写死了整页的区块扫描清单）会让模型把「本图里没有柱状图」报成 P0 差异 —— 实测五个分区共产生 11 条这类结构性幻觉。可比性靠 ground truth 与评分口径保证，不靠提示词字面相同

### 2.5 锚点探针（每区必做，先于判定）

送判定提示词之前，先用同一张区图问一个**答案已知、且在页面内部真实存在**的事实。

**真值绝不能取自拼图标注。** 实测中锚点失败的典型形态不是「我看不清」，而是**读到标注文字并当成页面内容**（问大标题，答「A — DESIGN (source of truth)」）—— 若用标注当真值，闸门会被自己的标注骗过去。

锚点失败 → **丢弃该区全部结论**，细分重试；连续失败标记「未判定」，不得计为「一致」。

## 3. 缺陷注入分类法

每个保真面至少注入一处，按难度分档。**难度分档是这个基准的核心** —— 只测易档等于没测。

### 易档（基线，命中不算通过）

| 保真面 | 注入示例 |
|---|---|
| 颜色 | 主强调色换到另一个色相（橙 → 黄），ΔE 足够大 |
| 文案 | 数字调换（412 → 421）、单词替换 |
| 素材 | 整块图形删除或明显错位 |

### 中档

| 保真面 | 注入示例 |
|---|---|
| 素材保真 | 线性图标替换为基本几何形（CSS 方块 / div 圆）—— 即「code-native 近似」 |
| 颜色 | 同色相内明度或饱和度偏移 15–20% |
| 布局 | 元素顺序调换、对齐方式改变 |

### 难档（**通过线设在这里**）

| 保真面 | 注入示例 |
|---|---|
| 字体排印 | 字重跨一档（800 → 500）、字号 ±2px、字间距变化 |
| 间距节奏 | 单处区块间隔改变 20–30px（如 32 → 10） |
| 圆角/阴影 | 圆角半径 ±6px、阴影扩散半径变化 |

**难档命中，才说明模型具备语义级判断力。**
只命中易档 = 它是 OCR + 取色器，撑不起保真判定。

### 注入纪律

- 一次一处，缺陷之间不重叠区域，否则归因不清
- 注入后**程序化校验**每处确实生效（字符串断言），不靠肉眼
- 记录 diff 行数，确认无意外改动

## 4. 评分维度

### 4.1 召回（v2 arm）

逐条对照注入清单：

| 判定 | 口径 |
|---|---|
| ✅ 命中 | 指出该元素的该类差异，**且方向正确**（"变细"不能报成"变粗"） |
| ⚠️ 部分 | 提到该区域异常，未说对是什么 |
| ❌ 漏 | 未提及 |

方向错误只记 ⚠️。方向错的修复建议会让循环朝反方向改。

### 4.2 误报与幻觉（v1 arm）

| 判定 | 口径 |
|---|---|
| 真实 | 人工核对确认图上确有该差异 |
| **幻觉** | 图上不存在，模型编造 |

**幻觉是这类系统最危险的失败模式**：它会让收敛循环去修不存在的问题，每修一次就离设计稿更远，且不会自行终止。

### 4.3 可执行性

对每条命中的差异额外评：

| 等级 | 口径 |
|---|---|
| A | 指明元素 + 说清 A 与 B 各是什么 + 可直接落到代码 |
| B | 指明元素与差异类型，但未给具体值 |
| C | 只说"某处不一致" |

**只有 A 级能驱动自动修复。** 一个召回率高但全是 C 级的模型，实际不可用。

### 4.4 稳定性（收敛循环的前提）

同一张对比图**独立跑 3 次**，统计：

- 三次都报的差异条目占比
- 只出现一次的条目占比

**稳定性差 = 循环不会收敛。** 每轮判定漂移，会出现「修好又被报出来」的震荡。这一维度比召回率更能决定方案成败，却最容易被忽略。

**二选一的方向类判定（哪边更粗 / 哪边更大）必须跑满 3 次才计分。**

实测教训：某模型一次答对「左边更粗」被记为难档命中，扩大到 15 次后只对 8 次 —— **二选一题上 53% 就是掷硬币**，那次命中是运气。更要命的是错误按**轮次**聚集：同一轮里五种送检方式几乎一致答错，下一轮又一致答对，单看任何一轮都像是稳定的。

方向错的修复建议会让收敛循环朝反方向改，比漏检危险。同一题三次答案不一致 → 记 ⚠️ 部分，不记命中。

### 4.5 成本

记录每次判定的 prompt tokens / completion tokens / 延迟。收敛循环要跑多轮，单轮成本 × 轮数才是真实代价。

## 4.6 提问方式：开放式 vs 逐保真面定向

**这一维度比模型选型更能决定成败，且极易被忽略。**

同一模型、同一缺陷（主标题字重 800→500，肉眼清晰可见、像素断言已过）：

| 提问方式 | 结果 |
|---|---|
| 定向：「A 和 B 的大标题字重一样吗？」 | 12/12 命中 |
| 开放：「你自己找，覆盖五个保真面」 | 漏检，该区块五项全报「一致」 |

**模型问到就看得见，不问不会主动去看。**

两种方式的失败模式方向相反，必须同时测：

| | 开放式 | 逐保真面定向 |
|---|---|---|
| 典型失败 | **假阴性** —— 只报最显眼的，难档全漏 | **假阳性** —— 每格必答，不确定时倾向说「不一样」 |
| 循环后果 | 提前判 `passed`，实际没修好 | 去修不存在的问题，不收敛 |

关键提醒：**开放式的低幻觉率有一部分是「懒」换来的** —— 大量回答「一致」，说得少自然错得少。
定向发问堵死了这条退路，因此必须回答：**省下的话被真判断填上，还是被编造填上。**

零差异对照（§2.2）让这个问题可测得毫无争议：设计稿对它自己逐格发问，
**每一句「不一致」都是幻觉，没有解释空间**。

评分口径（先定后测）：

| arm | 计什么 |
|---|---|
| 零差异 | 「不一致」条数 = 幻觉数；「无法判断」单独计，不算幻觉但计入弃权率 |
| 忠实实现 | 同上，另需人工核对每条是否确为真实残余差异 |
| 注入版 | 逐缺陷召回，重点看难档两项是否被定向问出来 |

判定：**难档召回提升 且 零差异 arm 幻觉 ≤ 1 条**，才算这个交换划算。
若召回上去了但幻觉也上去，说明模型只是在「被迫表态时倾向报差异」，不可用于自动收敛，
退回开放式并接受难档漏检（改用程序化比对补上，见 §4.7）。

## 4.7 该问模型的和不该问模型的

字重、间距、颜色值、圆角半径这些，**实现侧本来就能精确读出来**
（`getComputedStyle`、渲染后像素测量），拿去问视觉模型是舍近求远。

视觉模型不可替代的地方只有一处：**设计稿那一侧只有像素，没有 DOM。**

因此可行的分工是：
- 设计稿侧的量 → 视觉模型读（唯一途径）
- 实现侧的量 → 程序读（精确、免费、零幻觉）
- 两边比对 → 程序做

这条不改变本基准的结论，但会显著缩小视觉模型需要承担的判定面。
本规范测的是「视觉模型能承担多少」，不是「必须由它承担多少」。

## 5. 通过线

| # | 条件 | 理由 |
|---|---|---|
| 1 | **难档缺陷至少命中 1 项** | 证明具备语义级判断力，而非 OCR + 取色 |
| 2 | **v1 arm 幻觉 ≤ 1 条** | 幻觉会让循环发散 |
| 3 | **命中项中 A 级可执行性 ≥ 50%** | 否则无法驱动自动修复 |
| 4 | **稳定性：三次共同项 ≥ 60%** | 否则循环不收敛 |

四条全过才算「可用于生产收敛循环」。
只过 1、2 算「可用于人工辅助评审」。

## 6. 混杂因素与排除方法

| 混杂 | 表现 | 排除方法 |
|---|---|---|
| **降采样丢细节** | 难档全漏 | 记录 prompt tokens 推算有效分辨率；改用**局部裁剪放大图**复测同一缺陷。若裁剪后能看出，则是「看不到」而非「判断不出」，属工程可解 |
| **归一化残留** | 大量尺寸/清晰度类报告 | 提示词开头声明两图尺寸一致已对齐；仍频繁出现说明归一化没做好 |
| **提示词泄题** | 召回虚高 | 提示词只给保真面框架，绝不提示具体缺陷；同一提示词跑 v1 与 v2 |
| **顺序效应** | 总报右图有问题 | 交换 A/B 位置复跑，看结论是否跟着换边 |
| **区域偏好** | 只报顶部 | 提示词指定区域扫描顺序，并要求每区表态 |

## 7. 报告格式

```
模型 / arm / 耗时 / tokens

召回表   D1..Dn 逐项 ✅⚠️❌ + 原文引用
误报表   v1 arm 每条 → 真实 / 幻觉 + 人工核对说明
可执行性 每条命中 → A/B/C
稳定性   三次运行的条目交集比例
结论     四条通过线逐条判定
```

引用模型原文，不要转述 —— 转述会不自觉地把模糊表述美化成精确表述。

---

## 8. 这套规范的边界

本基准测的是**单轮判定质量**，不测**多轮收敛行为**。

即使四条通过线全过，仍需单独验证：
- 循环会不会在 P2 上反复横跳
- 修复引入的新差异会不会被识别
- 最大轮数与终止条件如何设定

那需要另一个基准（端到端收敛实验），不在本规范范围内。
