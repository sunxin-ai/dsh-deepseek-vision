# design-qa

`deepseek_vision` 把一张图交给外挂的多模态模型，只有回答的文字回来。图片**不进入你的上下文**，所以你看不到图 —— 你只能通过提问知道图上有什么。

**因此提问方式决定成败。** 下面四条是实测结论，不是风格偏好。

## 一、要读数，不要判断

| 提问形式 | 难档缺陷召回 |
|---|---|
| 「这两张图有什么区别」 | 0/2 |
| 「字重有区别吗」 | 0/2 —— 判定题，模型默认答「没有」 |
| **「A 和 B 的字重分别是多少」** | **2/2** |

「有区别吗」是判定题，模型倾向答否；「分别是多少」是读数题，它必须真的去看。

```
✅ 分别读出 A 和 B 中主标题的字重，用 CSS font-weight 数值估计（100-900）。
   只输出两行，不要解释：A: <值>  B: <值>
❌ A 和 B 的主标题字重一样吗？
```

**比较交给你自己做。** 拿到两个数再判断差异，比让它替你判断可靠。

## 二、绝不问「哪个更大」

实测同一段留白：问「哪个更大」→ 连续三次答反；问「哪个更小」→ 三次全对；读数 → 全对。

这是提问极性伪影，不是随机错误。**留白、间距类一律用读数式。**

## 三、必须指名到具体一对元素

```
✅ 特性卡片的底边与深色条顶边之间的那段空白，高度分别是多少？
❌ 元素之间的垂直间距有区别吗？
```

一张切片里往往有多段间距。不指名，模型会读另一段真实存在的间距，你会得到一个「正确但答非所问」的结果，并据此改错地方。

## 四、先过锚点，再信结论

判定之前先问一个**答案你已经知道、且在页面内部真实存在**的事实（一段文字、一个数字）。答错就丢弃这一轮的全部结论。

真值绝不能取自图上的标注文字 —— 模型会把标注读成页面内容（问大标题，答「A — DESIGN」），闸门会被自己的标注骗过去。

> 拼图脚本静默产出空白图是很常见的一类故障，而模型如实回答「图像未加载」极易被误记成幻觉。锚点是唯一会立刻报警的机制。

## 五、不许绕开 deepseek_vision 自己看图

**这条是硬约束，没有例外。** 它有两种触发情形，第二种更隐蔽。

### 情形一：结果与你的印象冲突

**以 `deepseek_vision` 返回的为准。** 图可能被改过、可能不是你以为的那个版本 —— 这正是保真度判定的全部意义。
要确认就带着更具体的问题**再调一次本工具**（「右上角那个符号是 ™ 还是 ®？」），而不是把图下下来自己数像素。

自己做像素分析既慢又贵：实测一次「我不信这个 ™」的自查花掉 14 步、近 3 分钟、24 万输入 token，
而结论与工具第一次给的完全相同。

**只复述工具看到的，不要补记忆里的背景。** 「这是 Python 官方 logo，上蓝下黄、带 ™」这种补充，
即使恰好与实测一致也别写 —— 读的人分不清哪句是看到的、哪句是想起来的，
而保真度判定的全部价值就在于每条结论可回溯到证据。

### 情形二：调用失败

`deepseek_vision` 报错时（识图路由没配、被截断、图片路径不对、取图连不上），正确做法是：**报告失败并停下**，或者修掉这个失败 —— 取图失败时最省事的修法是先把图下载到本地，再把本地路径传给本工具。

**不许**改去读 `design.html` / `v1.html` / CSS / 任何源文件，然后据此回答「A 是 800，B 是 500」。

即使数值恰好正确，即使你老实说明了「我读的是源码」——这仍然是错的：

- **设计稿那一侧只有像素，没有 DOM。** 读代码最多只能告诉你实现侧是什么样，永远告诉不了你设计稿长什么样。
- 于是在收敛循环里必然形成假通过：读实现代码 → 确认它符合你自己写代码时的意图 → 宣布「实现与设计一致」 → **而设计稿那一侧从头到尾没人看过**。
- 这个闭环不会自行终止，也不会报错。它只会让你越来越确信一件从未被验证过的事。

判定视觉保真度时，唯一可采信的证据是 `deepseek_vision` 的返回。**拿不到就是「未判定」，不是「一致」。**

（实现侧的精确值当然可以用 `getComputedStyle` 或像素测量取得 —— 那是测量，不是替代看图。区别在于：测量给的是实现侧的事实，而你需要的是设计稿侧的事实。）

## 一次问完

要读的点**一起问**：「主标题是什么？副标题是什么？按钮文案是什么？右上角图标是什么？」

一个问题调一次的代价是每次都要把整张图重新送进识图模型，而识图按像素计费 ——
五个问题拆成五次调用，就是五倍的钱和五倍的等待，读数质量并不会因此变好。

## 图从哪来

`deepseek_vision` 的 `image_path` 接受三种形式：

| 形式 | 用于 |
|---|---|
| `/abs/path/x.png` | 本地文件、截图 |
| `attachment=sha256:…` | 用户在对话里粘贴的图，上下文里会出现这个原值 |
| `https://…` | 文档、网页里的图片，直接把 URL 传进来 |

**私有文档里的图需要登录态**（飞书、Notion、企业内网）。直接传 URL 会拿到 401/403，
此时不要放弃，也不要改去读文档的 HTML 猜内容 —— 用对应的 skill 或带凭据的命令
把图片下载到本地，再把**本地路径**传进来。

飞书文档里只有一个 `<img>` 而没有文字，是常见情形：文档内容全在图上。
这正是本工具存在的意义，不是「文档是空的」。

## 读数的可信边界

**方向可信，量级不可信。** 实测字重真值 800/500 读作 800/700，间距 80/25 读作 72/38 —— B 侧总被拉向 A 侧。

所以：用读数判断「有没有差异、往哪个方向」，**不要把它当测量值**。实现侧的精确值用 `getComputedStyle` 或像素测量取得 —— 那是免费且零误差的。视觉模型不可替代的只有设计稿那一侧，因为那边只有像素、没有 DOM。

## 保真度判定要覆盖的五个面

字体排印 · 间距节奏 · 颜色 · 图形素材保真 · 文案内容

逐面单独提问，一次只问一个面。一次问全部，模型只会报最显眼的那处。
